# Appendix: Montage also runs the recorder controls

2026-11-07. This extends [`design.md`](design.md) (called `plan.md` when it was written) and replaces it where they disagree. Everything here is Linux only: gpu-screen-recorder doesn't run elsewhere, and on Windows and macOS these commands exit with an error saying so.

Montage becomes the single home for everything around gpu-screen-recorder: starting and stopping a recording, saving the replay buffer, the sounds, the post-save step, sharing, editing and the library. gpu-screen-recorder stays the program that captures the screen. It encodes on the GPU, and Montage doesn't replace that. The controls used to be shell scripts generated by Nix in the user's nixos-config; this appendix describes them exactly. Montage's commands reproduce that behaviour, then the scripts are deleted.

**Who does what:** this repository holds Montage, including its Home Manager module (below). The changes to the user's nixos-config (removing the scripts, pointing the shortcuts at Montage) are done separately, from that machine. The interface in this appendix is the contract between the two.

## Decisions made after the first version of the design

- **License:** AGPL-3.0, so `gifski` is used for GIFs.
- **One folder per clip,** inside gpu-screen-recorder's day folders. It holds the original (never modified), `montage.toml` (the edit), the exports and a `.thumbs/` cache:
  ```
  ~/Videos/Replays/2026-11-07/Replay_2026-11-07_21-03-11/
    Replay_2026-11-07_21-03-11.mp4        original
    montage.toml
    Replay_2026-11-07_21-03-11-share.mp4  what the automatic share makes
    Replay_2026-11-07_21-03-11-edit.mp4   editor exports; then -edit-2, -edit-3…
    Replay_2026-11-07_21-03-11.gif
    .thumbs/
  ```
  The recorder writes a single file into the day folder. Montage moves it into its own folder (named after the file, minus the extension) in the post-save step. Old loose files are moved the first time they're opened or exported. Deleting or moving a clip handles the whole folder, and deleting goes to the trash.
- **Captions:** any installed font (found through fontconfig's directories), from a searchable list where each name is drawn in its own font. The default is Impact, white with a thick black outline, in capitals (a toggle). Impact is pinned at the top and recent fonts follow it. If a saved font is missing, the caption falls back to Impact with a warning. The user's machine will get Impact from nixpkgs' `corefonts`.
- **No `/montage` Génie command.** `/clip` alone never opens the editor. Nothing is ever deleted automatically.

## The recorder as it ran before Montage

A systemd user service, `gpu-screen-recorder.service` (`WantedBy`/`PartOf` `graphical-session.target`, `After` `pipewire.service`), ran:

```
gpu-screen-recorder
  -w DP-5 -f 144 -k hevc -bm cbr -q 60000
  -a 'app-inverse:gsr-chime|default_input'      ← becomes two -a, one track each
  -c mp4
  -r 60 -replay-storage ram
  -df yes
  -o ~/Videos/Replays
  -ro ~/Videos/Recordings
  -sc <post-save hook>
  -ipc %t/gsr.sock
```

- **Before start:** `ExecStartPre` created `~/Videos/Replays` and `~/Videos/Recordings`.
- **Stopping:** `ExecStopPost` removes `%t/gsr-recording`. `KillSignal=SIGINT` and `TimeoutStopSec=5`, because it ignores SIGTERM. `Restart=on-failure`, `RestartSec=5`.
- **One process for both** the replay buffer (`-r`) and manual recordings (`-ro`), so only one NVENC session captures the screen.
- **What `-df yes` does:** it puts files in day folders (`…/Replays/2026-11-07/…`).
- **The `-sc` program** runs once a file is fully written, with the path as `$1` and `replay`, `regular` or `screenshot` as `$2`. It runs inside the service's cgroup, so anything it leaves running dies when the service restarts.

### The controls, exactly

All of them talk to the recorder through `gsr-cli -ipc $XDG_RUNTIME_DIR/gsr.sock <command>`. `gsr-cli` ships in the gpu-screen-recorder package. Montage runs it as a subprocess rather than reimplementing its socket protocol, which isn't a stable interface.

| Script | Key | Does |
| --- | --- | --- |
| `gsr-start` | Ctrl+Alt+Home | `start-replay-recording`. On success, creates `$XDG_RUNTIME_DIR/gsr-recording` and plays `device-added`. On failure, plays `dialog-error` |
| `gsr-stop` | Ctrl+Alt+End | `stop-replay-recording`. Plays `dialog-error` only on failure: the "saved" sound comes from the post-save hook, once the file is closed |
| `gsr-replay [N]` | Ctrl+Alt+Insert | `save-replay N`, N defaulting to 60. N must be a positive integer without a leading zero; anything else sends the notification "Clip not saved" / "“…” isn't a number of seconds." and plays `dialog-error`. N above 60 is capped at 60. `dialog-error` also plays if gsr-cli fails |
| post-save hook (`-sc`) | — | `replay`: plays `complete`. `regular`: removes `$XDG_RUNTIME_DIR/gsr-recording`, plays `device-removed`. Then, for every type, starts the share export (`gsr-clip-export`, which `montage share` replaces) at `nice -n 19`, `ionice -c 3`, in the background |

- **`gsr-recording` is read by another program.** The user's top-bar applet (Jauge) shows a red dot while it exists, as long as `gsr-cli status` succeeds. gsr-cli can't say whether a recording is running, which is why the file exists. This exact path and behaviour are kept.
- **Notifications** are sent with the app name `Montage`, everywhere.

### The sounds

Short `.oga` files from the freedesktop sound theme: `sounds/freedesktop/stereo/<name>.oga`, looked up under `$XDG_DATA_HOME` then `$XDG_DATA_DIRS`, never at a hard-coded path. They're played at the configured volume (0.6 by default) by:

```
PIPEWIRE_PROPS='{ application.name = gsr-chime }' pw-play --volume 0.6 <file>
```

The stream's `application.name` must be exactly `gsr-chime`: the recorder records every application except that one (`app-inverse:gsr-chime`), which keeps the sounds out of the clips. cpal can't set that property, so Montage runs `pw-play`.

The sound never delays the command: it's started and the command returns.

## Montage's commands, replacing all of the above

```
montage record start            was gsr-start
montage record stop             was gsr-stop
montage record toggle           new: one key for both
montage save [N] [edit]         was gsr-replay; N and edit in either order: save 15 edit, save edit 15, save edit
montage on-save <file> <type>   the recorder's -sc hook
montage share <clip>            headless share, also run by on-save
montage open <clip>             the editor
montage                         the library
```

- **`save … edit`** writes `$XDG_RUNTIME_DIR/montage-edit-next` before `save-replay` (and removes it if `save-replay` fails). `on-save` consumes it: when it's present and less than 10 s old, `on-save` runs `montage open` on the new clip instead of `montage share`. A stale flag is deleted and ignored. Only a `replay` consumes it.
- **`on-save`:**
  1. plays the sound for the type
  2. removes `gsr-recording` for `regular`
  3. moves the file into its own folder
  4. detaches the share or the editor from the service's cgroup with `systemd-run --user --collect` (the share also gets `--nice=19` and idle I/O)
  5. returns right away

  The detaching matters most for the clipboard: whatever serves the clipboard has to outlive a restart of the recorder. On Wayland the program that copied serves the clipboard, so `montage share` stays running, as the unit's main process, until something else is copied.
- **`share` on a `screenshot`** does nothing, and neither does `on-save`.
- **Run time:** every command except `open` and the library finishes in well under 100 ms. They're bound to keys and run from a launcher.
- **Exit codes:** non-zero on failure, so scripts and the launcher can tell.

`record` and `save` don't need the GUI: starting the binary for them doesn't initialise wgpu, fonts or FFmpeg.

## Recording settings live in Montage

The recorder's settings (screen, frame rate, codec, quality, replay length, audio sources, folders) are set in Montage's settings page, not in Nix. The service doesn't run gpu-screen-recorder with fixed flags: it runs **`montage recorder run`**, which reads `~/.config/montage/config.toml`, creates the two folders, builds the command line and `exec`s gpu-screen-recorder. The service then supervises gpu-screen-recorder directly, with no Montage process left running.

**The settings page** (in the editor/library window, also `montage settings`):

| Section | Settings |
| --- | --- |
| Capture | Screen (outputs listed from Wayland, shown by name and model, not just connector), frame rate, codec (HEVC, H.264, AV1), quality as a bitrate with a live "≈ N MB per minute" |
| Replay buffer | Length in seconds, with the RAM it takes at the current bitrate (60 Mbps × 60 s ≈ 450 MB), and RAM or disk storage |
| Audio | The tracks, in order: each is a source picked from PipeWire's devices and apps (default output minus the sounds, default mic, one app…), with a name ("Game", "Mic") |
| Folders | Replays and recordings |
| Sharing | The size budget and the bitrate rules |
| Sounds | On or off, and volume |

- **Saving the settings** writes `config.toml` and restarts the service (`systemctl --user restart gpu-screen-recorder`). A restart empties the replay buffer and ends a recording, so while a recording is running the page offers to apply after it stops, and it always says the buffer will be emptied.
- **Validation** happens before saving: Montage runs `gpu-screen-recorder --list-capture-options` and `--list-audio-devices` / `--list-application-audio` to offer only what works, and checks that the folders can be written to.
- **Montage's sounds are left out of the desktop track automatically.** It isn't a setting: `default_output` in a track becomes `app-inverse:gsr-chime`, and a track with other `app-inverse:` entries gets `app-inverse:gsr-chime` added.
- **Every other command** (`save`, `share`, `on-save`) reads the same file, so the replay length cap, the folders and the share budget can never disagree with the recorder.

### `config.toml`

```toml
track_names = ["Game", "Mic"]
# library = ["~/Videos/Replays", "~/Videos/Recordings"]   the default on Linux

[recorder]
monitor = "DP-5"
fps = 144
codec = "hevc"                 # hevc, h264, av1
bitrate_kbps = 60000
replay_seconds = 60
replay_storage = "ram"         # ram, disk
replay_dir = "~/Videos/Replays"
record_dir = "~/Videos/Recordings"
audio = ["default_output", "default_input"]   # one track each, in order

[share]
max_bytes = 20971520
fps = 60
audio_kbps = 128
min_video_kbps = 2000          # under this, cut the clip instead
hd_video_kbps = 4500           # from here up, 1080p instead of 720p
max_video_kbps = 8000

[sounds]
enabled = true
volume = 0.6
```

Every key is optional, and unknown keys are an error, so a typo doesn't go unnoticed.

## Home Manager module

The flake exports `homeManagerModules.default` (`nix/hm-module.nix`). It installs Montage, defines the recorder service, and gives the settings their first values. The settings themselves belong to Montage:

- **`config.toml` is a real, writable file,** not a store link. The module writes it only when it doesn't exist, from the options below. After that, the settings page owns it and a rebuild never overwrites it.
- **The service** is `ExecStart = montage recorder run`, with the `ExecStopPost`, kill and restart settings listed above, and `/run/wrappers/bin` first in its `PATH`, so a capability-wrapped gpu-screen-recorder wins.

The user's nixos-config only enables it, with the old values as the starting point:

```nix
programs.montage = {
  enable = true;
  recorder = {
    enable = true;               # the gpu-screen-recorder user service
    monitor = "DP-5";
    fps = 144;
    codec = "hevc";
    bitrateKbps = 60000;
    replaySeconds = 60;
    replayDir = "${config.home.homeDirectory}/Videos/Replays";
    recordDir = "${config.home.homeDirectory}/Videos/Recordings";
    audio = [ "app-inverse:gsr-chime" "default_input" ];  # one track each, in this order
  };
  share = {                      # gsr-clip-export's numbers
    maxBytes = 20 * 1024 * 1024;
    fps = 60;
    audioKbps = 128;
    minVideoKbps = 2000;         # under this, cut the clip instead (replay keeps its end, recording its start)
    hdVideoKbps = 4500;          # from here up, 1080p instead of 720p
    maxVideoKbps = 8000;
  };
  trackNames = [ "Game" "Mic" ];
};
```

Also: `recorder.package` (default `pkgs.gpu-screen-recorder`, also used for `gsr-cli`), `recorder.replayStorage`, `sounds.enable` and `sounds.volume`.

- **The recorder flags:** `montage recorder run` adds `-sc` and `-ipc $XDG_RUNTIME_DIR/gsr.sock` itself. They aren't settings. The hook is `$XDG_RUNTIME_DIR/montage/montage-on-save`, a link to Montage made at each start: started under that name, Montage acts as `montage on-save`. A plain path works however the recorder treats spaces in `-sc`.
- **What it doesn't do:** it doesn't bind keys or write Génie's command list. The user's config does both, pointing them at the commands above.

## Phases, revised

The phases in the design stay, except that **phase 1** becomes: the CLI (`record`, `save`, `on-save`, `share`, `recorder run`), `config.toml`, the folders, the two audio tracks and the Home Manager module with the service. That's everything needed for the nixos-config switch-over, which removes the scripts, `gsr-clip-export` and the service definition there, and points Ctrl+Alt+Home/End/Insert and Génie's `/record`, `/stop-record` and `/clip` at Montage. Phase 1 comes right after the phase 0 spike, before the editor. The settings page comes with the editor window in phase 2. Until then, `config.toml` can be edited by hand.

`/clip edit` (old phase 3) is then just `save … edit`, which phase 1 covers, plus `montage open`, which arrives with the editor in phase 2.
